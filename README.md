# 纸舟 · Zhizhou Publisher

**把文件夹里的内容，送到你准备发布的地方。**

纸舟是一个在本机运行的内容发布工作台：读取 Markdown、图片与视频，按平台预览，再通过可见浏览器上传素材、填入文案。支持微信公众号、小红书、抖音图文、抖音视频和 B 站视频，无需模型 API。

> 网页模式默认停在平台编辑器，由你核对内容并点击发布。微信公众号另外提供官方接口模式，需自行配置凭证和接口权限。

## 文章与视频，独立管理

左侧「图文文章」「视频作品」是两个同级内容库：

- **图文文章** → 微信公众号、小红书、抖音图文；保存在 articles/。
- **视频作品** → 抖音视频、哔哩哔哩；保存在 videos/。
- 视频直接导入 MP4，不需要创建 article.md。切换平台时分别编辑标题与简介，视频本体共用。
- 小红书原始配图与文字卡片仍可切换；视频横竖屏按原始比例预览。

旧版文章中附带的视频会在启动时复制、校验并迁入视频库，保留原始文件、历史截图及记录。混合图文文章仍保留；视频删除移入本地回收目录，不会被再次迁移恢复。

## 支持哪些工作流？

| 平台 | 内容与预览 | 执行方式 |
| --- | --- | --- |
| 微信公众号 | Markdown 长文、段落内插图、封面、作者、摘要 | 网页自动填入、尝试保存草稿；也可用官方接口创建草稿与申请发表 |
| 小红书 | 独立短文、顺序图片、3:4 文字卡片 | 上传图片并填入标题、正文，人工核对后发布 |
| 抖音图文 | 独立短文与图片列表 | 打开创作页、上传配图、填入文案，人工发布 |
| 抖音视频 | 独立视频、平台文案、封面与播放预览 | 上传视频并填入标题和说明，人工确认转码、封面与发布设置 |
| 哔哩哔哩 | 视频、独立标题、简介、标签及投稿备忘 | 上传视频并填入标题、简介和标签，人工核对分区、封面、声明后投稿 |

同时提供：

- 文章搜索、排序、创建时间展示与文章管理。
- 小红书「原始配图 / 文字卡片」可逆切换，保留另一套素材。
- 图片列表管理，各平台可使用不同文案和素材。
- 分页发送记录、现场截图、手动确认发布结果。
- 内容版本识别与重复提交保护；结果不明确时不自动重发。
- 平台独立浏览器会话，关闭窗口后可重新打开并复用登录状态。

## 快速开始

目前主要面向 **Windows + Microsoft Edge**，需要 Python 3.10 或更高版本。其他系统尚未验证。

~~~powershell
git clone https://github.com/rookiezzZ333/zhizhou-publisher.git
cd zhizhou-publisher
~~~

1. 双击 **安装依赖.cmd**，创建项目内的 Python 环境并安装依赖。
2. 双击 **启动.cmd**，浏览器会打开 [本地工作台](http://127.0.0.1:8766)。
3. 点击「选择文章文件夹」，导入文案与素材；也可以把内容直接放进项目的 articles/ 后刷新列表。
4. 选择平台，核对预览，再点击「自动填入」。
5. 首次使用在专用 Edge 窗口扫码登录；填写完成后在平台页面检查并发布。
6. 发布视频时，切换左侧「视频作品」→「导入 MP4 视频」，再选择抖音或 B 站。

喜欢命令行也可以：

~~~powershell
py -3 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe launcher.py
~~~

浏览器自动化复用已安装的 Edge，无需额外下载 Chromium。服务仅监听 127.0.0.1。若端口被占用，可设置 ZHIZHOU_PORT 环境变量后重新启动。

## 一篇内容，一个文件夹

~~~text
articles/
└── my-article/
    ├── article.md              # 公众号长文及共用配置
    ├── images/
    │   └── 01-cover.png
    ├── xiaohongshu.md          # 小红书独立文案
    ├── xiaohongshu/            # 原始配图 / 文字卡片
    ├── douyin.md               # 抖音图文独立文案
    └── douyin/                 # 抖音图文配图

videos/
└── my-video/
    ├── video.yaml              # 视频文件、封面、创建时间与 B 站备忘
    ├── douyin.md               # 抖音视频标题和简介
    ├── bilibili.md             # B 站视频标题和简介
    ├── cover.jpg
    └── media/
        └── video.mp4
~~~

仓库提供 [最小示例](examples/hello-zhizhou)，可以直接导入。个人文章、视频、生成素材和登录信息默认不纳入 Git。

### 主文案

article.md 推荐写法：

~~~markdown
---
title: 我的文章标题
author: 作者名
digest: 这是一段简短摘要。
cover: images/01-cover.png
xhs_title: 小红书短标题
tags: [创作分享, 效率工具]
---

# 我的文章标题

这是文章开头。

![封面](images/01-cover.png)

## 第一个观点

在这里展开内容。

![示例](images/02-example.jpg)
~~~

图片按数字自然排序，支持 PNG、JPG、JPEG、WebP，也兼容 image/ 目录。公众号按 Markdown 图片标记的位置排版；完全没有图片标记时，按顺序追加到文末。未设置 cover 时使用首张图片。

不自动下载远程图片，也不读取文章文件夹之外的文件。正文不做自动压缩、截断或改写。

### 平台独立文案与图片

文章目录的 xiaohongshu.md、douyin.md 和视频目录的 douyin.md、bilibili.md 都以一级标题作为该平台标题，之后为正文：

~~~markdown
# 给时间按下播放

一段关于作品的说明。

#视觉设计 #创作分享
~~~

在主文案配置区可增加：

~~~yaml
xhs_images:
  - xiaohongshu/01.png
  - xiaohongshu/02.png
douyin_images:
  - douyin/01.png
douyin_title: 抖音图文短标题
douyin_video: douyin-video/video.mp4
~~~

未配置独立图片时沿用文章配图。未提供抖音独立短文时会提示沿用小红书短文；视频在独立视频库编辑，不再沿用文章文案。

### 小红书文字卡片

在小红书页签点击「生成小红书文字卡片」，将已有短文排版为 1080×1440 图片。通过「原始配图」「文字卡片」切换要上传的素材，两套文件都保留。

此功能负责排版，不生成教程内容；请先写好步骤、条件和结论。它不会改动公众号内容。

### 抖音与 B 站视频

进入左侧「视频作品」，导入 MP4 或选择已有作品，再点击「抖音视频」或「哔哩哔哩」。编辑并保存本平台文案，播放预览后点击自动填入。

- 工具的视频导入上限为 **500 MB**；文件夹整体导入上限为 **80 MB**。视频请从视频库独立导入，不受文章文件夹导入上限影响。
- MP4 的编码是否能播放、是否被平台接受，需通过本地预览和平台上传确认。
- 转码完成、封面裁剪、话题匹配、原创 / AI 声明、可见范围和发布时间，需要在对应平台检查。B 站的分区、创作类型和转载来源可先写入本地备忘，但不会代替平台选项。
- 文案中的 #话题 不代表已经选中平台对应的话题。
- 本项目不内置视频生成功能，视频需自行准备。

详细规则见 [各平台独立内容](PLATFORM_CONTENT.md)。

## 登录与微信公众号接口

网页模式由 **Python Playwright** 控制可见的 Microsoft Edge。程序定位网页输入框与上传控件，选择本地文件、填写文案，并核对页面反馈。

B 站适配目前通过本地模拟页面测试，尚未以真实账号验证上传转码和当前页面兼容性。

各平台使用 .state/ 内的独立浏览器目录保存会话，不复制日常浏览器的 Cookie。普通浏览器已经登录，并不代表项目专用窗口已登录；首次仍需扫码。

微信公众号默认可使用网页模式。若选择官方接口模式：

1. 在「账号连接」填写自己的公众号 ID、AppID 和 AppSecret。
2. 在微信后台配置实际出口 IP 白名单。
3. 确认账号具备草稿及发表相关接口权限。
4. 先测试连接，再创建草稿或提交发表。

官方接口的「发表」不等于向粉丝「群发」；当前未实现粉丝群发。

AppSecret 保存在本机 .state/settings.json，为明文；也可通过 WECHAT_APP_SECRET 环境变量提供。前端不会回传已保存的密钥。不要分享 .state/，其中包含凭证、浏览器会话、发布记录及现场资料。

## 怎么判断是否发布成功？

「已填入，待核对」只表示自动填写完成，不表示平台已发布。

如果已经在平台手动发布，可以在发送记录里使用「我已手动发布」确认。该状态明确标记为用户确认，不冒充平台自动检测。程序异常或结果待核实时，应先查看平台后台，避免重复发布。

删除记录不等于删除平台文章；隐藏记录仍保留防重复信息。移除配图保留原文件，文章删除操作以界面确认提示为准。

## 项目结构

~~~text
app.py              本地 HTTP 服务、导入与发布任务
launcher.py         启动器及浏览器打开逻辑
publisher/          内容解析、卡片排版、平台适配、状态管理
web/                原生 HTML / CSS / JavaScript 工作台
tests/              单元测试与模拟编辑器测试
scripts/            可选排版检查工具
examples/           可导入的公开示例
articles/           本机文章与图片（不提交）
videos/             本机独立视频与平台文案（不提交）
.state/             本机凭证、浏览器会话和记录（不提交）
outputs/            本机生成产物（不提交）
~~~

技术栈：Python、Playwright、HTTPX、SQLite、Markdown-it-py、PyYAML、Pillow，以及原生前端。不需要 Node 构建步骤或模型 API 密钥。

## 开发与测试

~~~powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
~~~

部分集成测试使用已安装的 Edge。可选的微信上游排版检测器不随仓库分发，未安装时相关测试会跳过；配置方法见 [测试说明](TESTING.md)。

网页适配会受到平台改版、登录状态和账号权限影响。模拟页面测试不代表所有账号和当前平台页面都可正常发布；扫码、验证码和审核由用户与平台处理，程序不绕过这些限制。
